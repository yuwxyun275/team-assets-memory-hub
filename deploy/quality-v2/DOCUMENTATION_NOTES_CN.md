# 后续用户文档与 UI 截图要求

用户要求：正式撰写说明文档时，纳入原始会话导入方式、实现边界和真实 UI 截图。本文记录待写内容，不代替最终用户文档。

## 必须讲清楚的输入方式

- 原始资料不需要预先整理成完善的经验总结；员工与 AI 的开发会话、错误尝试、修复过程和测试输出都可以作为分析材料。
- 页面目前接受文本文件。JSONL 按会话类型处理，TXT／Markdown 按文档类型处理；尚未按各 CLI 的格式专门解析角色、轮次和工具调用，也没有通用的长会话自动分段整理。
- 项目路径、版本、适用范围和可见范围仍需填写。单文件最多 60,000 字符，整批请求最多 140,000 UTF-8 字节，超限需要拆分。
- 系统保留来源、内容指纹与原文引用，结合授权范围内的已有资产，判断复用、修订、生成经验或流程候选。无足够证据时可以不生成。
- 候选需经过内容评估与负责人审核。来源引用命中、上传的“测试通过”文字、审核通过，都不能单独冒充本系统独立执行验证或效果增益。
- 普通上传默认非合成资料，页面已移除模拟资料勾选项。预置演示文件以首行来源标记保留合成属性；非合成标记不是内容真实性认证。

## 演示环境与真实能力的区别

- 2026-09-14 用户明确：暂缓的是大规模对照实验，一条资产必须完整走真实模型链路。当前 localhost 体验已切换真实 DeepSeek，独立团队「真实模型体验 · 库存」保留真实结果；旧固定响应演示留在旧团队，不混入本次检索。
- 文档输入示例跑通不能替代杂乱历史 Session 的真实模型验证。
- 一条真实运行不能推出普遍提炼质量、任意会话处理效果、收益或统计结论。示例工程／约定的合成来源与模型是否真实调用是两个维度，文档必须分别说明。
- 已实际完成首个无资产修复、3 项独立测试、真实轨迹提炼、基于来源修订与负责人发布，以及后续真实采用和 5 项验证。自动回流还有复用建议和未发布的修订候选。最终采用证据见 walkthrough-rICaGG/real-reuse-receipt.json（会话第 2 轮）；不得把调试轮次计为独立收益实验。完整体验步骤见该目录的体验指南.md。保留引用失败、审核驳回与集成修复历史，业务验收和贡献证明仍独立展示。

## 正式文档需要采集的 UI 截图

1. 资产质量中心：新版填写分组、深灰色占位示例、项目路径与版本说明。
2. 原始资料选择与可见范围：显示中文示例文件或适当脱敏的原始会话，不再显示模拟勾选框。
3. 提炼记录：展示实际完成的学习任务、分流结果与候选入口。
4. 候选详情：来源引用、内容评估、适用边界和负责人发布操作。
5. 任务看板：实际召回、读取、采用、验证证据及效果待观察状态。
6. 回流与下一任务复用：只使用实际产生的记录截图，不构造成功或贡献状态。

写作时从当时正在运行的 UI 重新截图，与正文步骤一一对应。页面截图不得包含登录密钥。尚未完成的步骤使用文字说明待验收，不以概念图冒充真实截图。
