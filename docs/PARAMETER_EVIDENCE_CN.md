# 参数设计、证据与复现

当前实现将参数分为**数学定义、治理策略、经验选择、容量约束**。只有经验选择可以从开发数据挑选。门槛、风险容忍度和容量预算应公开其取舍，不能包装成统计最优值。

本次已经完成代码改造、离线比较、审核记录重放和有界真实模型确认。结论是：**选定策略提高了本地契约任务的必要知识覆盖，但没有证据证明它提高真实模型完成率或降低总成本。**

## 1. 决策链与配置位置

1. Core 核验身份、权限和固定发布版本。编排器将未发布、已纠错、废弃、版本或绑定仓库不兼容的项提前排除。
2. 三路检索得到 BM25、向量和结构信号。原生向量可用时融合原生分数，否则用 TF-IDF 余弦。
3. 使用一次等权 RRF 融合名次，不把 RRF 与其原始输入再次加权。
4. 对已审核正文和按需读取卡片统一使用 Core 的 U，避免叠加旧版本地反馈。使用有界的 U 修正相关性，选择满足能力与容量限制的内容，去除明确同源同版本或相同内容的重复。
5. 只有送达、实际行为和验证分别产生证据后，才推进对应状态。

主要设置：

- Python：[`decision_policy.py`](../evaluation/team_asset_bench/team_asset_bench/decision_policy.py)。每条 recalled 记录带策略配置及 SHA-256。
- Core：[`decision-policy.ts`](../MemoryCore/src/asset-quality/decision-policy.ts)。Q、U 与治理策略版本。
- 质量评分策略：`intrinsic-quality/v3`。历史 v2 报告保留当时分数，不回写。
- 完整实验：[`parameter_calibration`](../evaluation/parameter_calibration/README.md)。

## 2. 参数台账

| 参数 | 当前值与作用 | 性质 | 由来与限制 |
| --- | --- | --- | --- |
| RRF 通道权重 | BM25、Vector、Graph 等权 | 方法约定 | 缺少可靠的通道重要性标签，不预设 1/.85/.75 差异。RRF 只组合一次 |
| RRF k | 10 | 经验选择 | 开发集比较 10/30/60/100。保留集与 k=60 的覆盖相同，无普适最优结论 |
| 候选窗口 | 24 | 经验选择兼容量限制 | 比较 12/24/48 后按开发集目标选出 |
| 相对分数底线 | 0.2 × 本轮最高分 | 经验选择 | 比较 .2/.4/.6。不是相关概率阈值 |
| 外层九类加权 | 已停用 | 简化 | 版本与权限做门禁。质量做发布条件。成本做预算。旧算法只留作对照 |
| U 对排序影响 | `score = RRF × (1 + .05 × (2U_eff - 1))` | 治理策略 | U_eff 是适用性修正后的 U。即使到极端值也最多改变相关性分数 ±5%。不是经验最优幅度 |
| 四维 Q | 各 25%，均值取整 | 评分约定 | 四维同等重视，消除未证实的 40/25/20/15 差异。不是正确率 |
| E | 有结论且有引用的模型检查项占比 | 数学定义 | 有依据的否定也计入覆盖，E 不代表合格率 |
| 发布门槛 | 全局默认 Q≥80，团队可显式配置 | 治理策略 | 保留原门槛。数据缺少独立的合格标签，不能声称 80 或 85 最优 |
| 发布其他条件 | 必查项通过，证据核验，负责人批准 | 硬约束 | 高分不能绕过失败或未知项。不能自动发布 |
| U 先验 | Beta(5,5)，无样本返回未知 | 影响预算 | 单条独立观察使均值变化最多 1/22≈4.55 个百分点。对称先验不偏向好或坏 |
| 人工/模型权重 | 都为 1，同任务只保留一票 | 证据规则 | 无依据假定人工始终为模型两倍。人工纠正替换对应当前评价 |
| 时间衰减 | 保留期内停用 | 移除无依据参数 | 没有长期标注数据支持 90 天指数尺度。版本变化、明确纠正与保留期仍隔离证据 |
| 场景迁移 | 仓库、环境、任务类型、版本相同，规范化词项 Jaccard=1 | 保守治理边界 | 近似语义迁移无独立标签。默认只迁移词项完全一致的场景，不声称理解语义等价 |
| 适用性修正 | 至少 3 个任务，`Δ=.05(A-B)/(10+A+B)` | 治理策略 | A/B 是适用/不适用任务数。限定最低观察数和最大影响，不是统计显著性门槛 |
| 不确定性 | Beta 后验标准差与 95% 等尾区间 | 条件统计模型 | 依赖可交换投票假设，不是模型准确率区间或因果收益区间 |
| 条数/Token | 每项任务的 `max_assets`、`token_budget` | 容量约束 | 本次比较固定为 8 项、6,000 估算 Token，未修改全部运行任务为此预算 |
| 保留期与队列 | 30 天、日 200、队列 50、并行 1 的默认值 | 运维策略 | 可由团队配置。受容量、费用与保留要求约束，未伪装成质量最优值 |

### 仍属于检索后端启发式的量

BM25 的 k1=1.5、b=.75，原生分数与本地分数的 .8/.2 混合，以及本地结构打分中的路径优先项，是现有检索后端的启发式设置。本次固定这些量以比较**选择层**，没有把它们标为已校准。它们的原始数值在新策略中只影响各路内部名次，不再与 RRF 直接重复加分。需要切换原生 embedding、语言或语料规模时，应重新运行同一验证协议。

这不是遗漏一个待补版本，而是明确本次能够验证的范围。没有对应数据时给出“所有参数都已最优”会是不实结论。

## 3. 排序选择的证据

协议在执行前保存为 [`protocol.json`](../evaluation/parameter_calibration/protocol.json)。候选空间为 46 组：旧方案 1 组、BM25 9 组、RRF 36 组。

- 400 份资产来自四个示例项目和四种表示。
- 9 个开发任务来自 flags、inventory、webhook。3 个保留任务都来自 billing。
- 所有任务共享固定语料。资格由原始契约缺陷标签模拟，比较的是通过资格条件后的选择，不是端到端审核准确率。
- 不把同一规则在 Wiki、会话和 Skill 中的多份表示重复记作必要知识覆盖。
- 选择顺序：门禁零违规 → 开发任务必要信息组平均覆盖最大 → 超出指定必要集合的比例最小 → 估算 Token 最少 → 简单配置优先。
- “超出指定必要集合”不代表这些资产绝对无用。它只是保守的任务范围指标。

| 方案 | 开发集平均覆盖 | 保留集平均覆盖 | 保留集平均估算 Token |
| --- | ---: | ---: | ---: |
| 旧权重 | 19.44% | 25.00% | 1,982.67 |
| BM25 简化基线 | 64.81% | 58.33% | 2,501.00 |
| RRF k=60、底线 .4、窗口 24 | 67.59% | 91.67% | 3,366.33 |
| 选定 k=10、底线 .2、窗口 24 | 70.37% | 91.67% | 3,366.33 |

旧版和新策略还改变了资格过滤位置、内容去重与集合选择。不能将整组收益都归因于 k。保留集只有一个仓库，不报告不可靠的总体置信区间。详细每任务结果和所有候选见 [`ranking.json`](../evaluation/parameter_calibration/results/ranking.json)。

方法依据是 [RRF 原始论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)：根据各路排名相加，避免假定原始分数尺度相同。论文固定 k=60，不能证明本项目应取 60。本次将它纳入比较，保留所有候选结果。按组分开开发与测试的原则参见 [scikit-learn GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)。本次使用的是事先固定的仓库留出，并未宣称运行了交叉验证。

## 4. Q/E 的依据与已知错误修复

400 份存档审核实际调用过真实模型。80 份是作者故意构造的来源冲突、测试造假或图锚点错误。其他 320 份仅标为“可进入审核”，没有独立专家合格标签。

重放结果：旧权重与四维等权在门槛 80 下，开发集均漏过 1/45 个明确缺陷，保留集均为 0/35。门槛 85 的缺陷漏过为零，但未标注资产的通过量也下降。没有合格标签，无法判断这部分是正确拦截还是误拒，因此**不据此提高或降低全局发布门槛**。

漏检来自 Skill 中删除失败测试并报告成功的指令。已加入窄范围的验证诚信规则。命中时标为未知、要求澄清，即使模型高分也不能进入正常发布。规则对明确的“禁止删除失败测试”警告不误作操作指令。它不声称能识别所有语义变体。

此规则在发现缺陷后补充。重放证明该已知漏检被挡住，不是新的独立泛化评测。原审核记录和源哈希保留，新规则不会改写历史发布。

## 5. U 的数学含义

`U = (5 + P)/(10 + P + N)`，P/N 是当前证据有效且去重后的 helpful/harmful 任务数。它是带收缩的观察汇总，不是“这次任务成功的概率”。

- 没有正负样本时返回 `null`，不是 0 或一项声称观察到的 50 分。
- 一个正样本：6/11≈.5455。两个相反观察：6/12=.5。
- 对称 Beta 先验的两侧各 5 份伪计数体现保守影响预算，不冒充真实任务。
- 返回的可信区间以这个投票模型为条件，不代表人类已确认的准确率。
- 内容错误、观察不足和不适用不简单等同于 harmful。分别进入纠正或适用性处理。
- 生效前必须核对当前窗口证据哈希、资产版本和环境，重复观察不累加成独立试验。

`U_eff = clip(U - penalty + Δ, 0, 1)` 是传给排序器的有效值。penalty 为 `.05 × 不适用数 / (10 + 不适用数 + 有效反馈数)`。Δ 的条件和上限见参数台账。无有效观察时使用中性先验参与排序，不将其展示为已观察到的效果。

Beta 分布的 CDF 与分位数定义可参见 [SciPy 官方文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.beta.html)。先验强度是本系统的影响预算选择，不是该文档推荐值。

## 6. 新增真实模型确认

本次另行运行了 12 次请求，请求模型名为 `deepseek-v4-flash`，供应方实际返回的模型名为 `deepseek-flash`。两个任务是库存幂等和账单舍入。三个条件是无资产、旧策略和选中策略。每个任务条件重复两次，顺序用固定随机种子打散。各条件相同温度、4,096 输出 Token 上限、初始代码与验收测试。

| 条件 | 验收通过 | 输出截断 | 输入 Token 合计 | 输出 Token 合计 |
| --- | ---: | ---: | ---: | ---: |
| 无资产 | 1/4 | 3/4 | 2,604 | 14,655 |
| 旧策略 | 3/4 | 1/4 | 7,924 | 13,357 |
| 新策略 | 2/4 | 2/4 | 9,602 | 16,244 |

6 次截断都耗尽额度，只产生推理，没有完整代码。没有删除失败，也没有仅重试落后的条件。**这组实验没有证明新策略提高真实完成率**。它说明生成预算会成为独立瓶颈，离线知识覆盖不能替代端到端结果。

这是代码生成微实验，不是新的一组 CodeBuddy CLI 全链路对照。模型只看到任务描述、基线代码与选中资产。验收脚本不进入提示词，并在 macOS 沙箱中只读执行。模型返回的 `used_assets` 只是自述，不被自动当作系统可信 `asset_used` 事件。

原始 usage、finish_reason、测试输出、生成代码和哈希见 [`live-confirmation.json`](../evaluation/parameter_calibration/results/live-confirmation.json)。输入与输出分别记录，不把缓存 Token 重复累加。当前单价未核实，所以金额未知。此微实验没有后台调用，历史资产建设与人工审核费用明确排除，不声称总成本。

## 7. 什么已经完成

参数从散落常数变为有版本的配置。重复信号被移除，质量与适用性不会再被混成相关性加分。实验协议、候选、选择结果、保留集和真实失败均可复现或核对。代码通过对应回归检查，PDF 与实现使用相同定义。

“最终交付”指实现、文档和证据齐备。它不意味着有限样本足以证明永远最优。遇到新分布时应重新运行同一验证协议，而不是继续凭感觉填写更多小数。
