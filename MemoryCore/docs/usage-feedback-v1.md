# 使用效果异步评估：纠错、人工处理与任务回执

2026-09-11 增量实现见 [推荐前场景与使用后效果反馈](SCENE_CONTEXT_FEEDBACK.md)。下文保留前一轮实现范围与测试记录，不代表当前全部能力。

## 本次实现范围

- 只修改后台使用效果评估及 Panel 展示，不修改 CodeBuddy 对话模型、Proxy 卡片注入或原资产正文。
- 网络失败与格式/证据失败分开处理；评价结果、回执及失败信息与观察记录通过同一次 CAS 写入持久化存储。
- 任务详情新增“资产使用效果回执”，质量中心新增“使用评估：人工待处理”。
- `helpful` 是观察性评价，不会伪造 `used / validated / contributed`。原生工程验证、贡献对照与任务状态保持原样。

## 后台处理规则

1. 当前任务/会话的后续事件进入 durable exposure；已有事件 ID 幂等去重，不能覆盖成不同内容。
2. 后台调用已配置的评价模型，每次最多 60 秒。普通 CodeBuddy 对话不等待该结果。
3. 网络失败按 5 秒、10 秒等退避等待重试；单次评估最多 3 次调用（含首次）。未配置模型、鉴权错误、疑似凭据输出直接转人工。
4. JSON、字段、缺少引用、引用不匹配：保存程序生成的具体错误，把错误、最多 12000 字符的安全旧回答及原始材料交回模型纠正。旧回答不是证据，不允许为通过检查编造引文。
5. `unobserved` 是成功完成但证据不足，不是失败，不触发无意义的纠错。只有助手自述时降为 `unobserved`。
6. 重试耗尽后保留失败记录；新事件不会重新激活失败任务。本人或团队管理员/审核者可填写原因后显式重试。每条曝光累计调用上限 20 次，达到上限后仍可人工评阅。
7. 失败分类包括 `upstream_timeout`、`upstream_request_failed`、`upstream_rate_limited`、`upstream_auth_error`、`reviewer_not_configured`、`invalid_json`、`invalid_format`、`missing_evidence`、`invalid_citation`、`unsafe_result`。

## 证据与并发边界

- 引用的事件 ID 必须存在，quote 必须是该事件的连续原文；`helpful/harmful` 至少引用工具结果或明确用户反馈。原文存在不等于语义判断一定准确。
- 结论绑定当前事件窗口哈希。新增消息后旧结论可保留供审计，但不得继续当作新窗口的有效结论更新 U。
- CAS 版本检查阻止迟到的模型回答覆盖新事件或人工评价。任务/会话/用户/资产版本/环境组成去重键；重复注入不是多个独立效果样本。
- 人工反馈注明来源并绑定窗口；可以纠正自动评价，不改变内容质量 Q 或发布状态。
- 原文及效果记录按团队现有保留期删除；人工待处理页面显示到期时间。不是无限保留。

## 回执存储与读取

`exposure.data.effect_receipt` 与评估状态在同一次存储写入中提交。包含资产 ID、发布 revision、任务、会话、事件哈希、评价、原文引用、工具调用 ID、错误、重试次数与保留期限。

任务通过 `asset/quality/task-receipt` 读取去重的当前结果，每 5 秒刷新页面。服务端从持久化 exposure 重建该投影，兼容旧记录，也避免独立写 Task metadata 时与原有 Trace/CI 发布器相互覆盖。删除/过期观察后，结果不再出现在回执或效果评分里。

**这是效果回执，不是把模型 helpful 转成贡献计数。** 测试证据与资产归因没有完成匹配时，原来的六阶段计数仍不会被人为改成通过。

新增接口（均要求用户鉴权及当前团队有效成员身份）：

- `POST /v3/meta/asset/quality/task-receipt`：`team_id, task_id`。普通成员只看本人且仍有读权限的资产观察；管理员/审核者可查看本团队记录。
- `POST /v3/meta/asset/quality/failed-uses`：`team_id`。管理员/审核者读取人工队列。
- `POST /v3/meta/asset/quality/retry-use`：`team_id, exposure_id, note`。本人或管理员/审核者显式重试。
- 原 `feedback` 接口支持人工解决失败记录，人工结果与模型结果区分。

## 验证范围

- Core：使用效果新增 14 项契约测试，覆盖超时、格式修复、证据纠错、无证据、有限重试、重启恢复、人工介入、并发迟到、版本/会话隔离、去重与保留期。另增加 SDK 纠错请求测试、HTTP 路由与权限测试。相关回归共 124 项通过。
- Panel：5 项 action/分页转发测试通过；后端 TypeScript 构建、前端 TypeScript + Vite 构建通过。
- 在本地部署后的真实网页核对任务效果回执、人工待处理队列及列表分页。未重新执行旧 CodeBuddy 六组实验，未将契约测试模拟模型的结果当作新的真实模型准确率。
- 原生正文完整性识别、CI/反事实贡献归因不在这次修改范围内，不能因为新增效果回执就声称它们已全部修复。

## 部署和回退

`node deploy/quality-v2/deploy-usage-feedback.mjs --apply` 部署 Core 与 Panel；`--component hub` 可只更新 Panel。默认不带 `--apply` 仅列出计划。

脚本先构建覆盖镜像，保留原容器，停机备份可写数据卷，保持原环境变量、挂载和网络。健康检查失败时恢复旧容器。私有备份含配置凭据，仅保存在本机受限目录，不应提交或对外分享。
