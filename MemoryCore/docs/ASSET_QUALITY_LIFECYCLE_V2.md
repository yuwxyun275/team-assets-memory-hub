# 资产质量闭环 v2：实现与操作说明

## 1. 边界与入口

入口：Memory Hub 左侧「资产质量中心」（`/#/quality`）。

本版实现的是**明确内容单元的发布评估，以及该版本被使用后的证据反馈**，不是给一个知识库容器的所有现在/未来内容统一盖章。

个人资产保留在个人空间时不强制调用评估模型。成员准备发布为团队资产时，在质量中心提交正文、用途和支持材料。队列自动评估，负责人或 reviewer 核对报告后批准。新正文、来源、用途、内容版本、元数据版本或评估策略变化需重新评估；普通召回只读取已发布快照和已有分数，不再次执行内容评估。

原有「approved」元数据不能代替新流程的发布记录；没有有效审核版本的共享资产会被使用权限检查挡住。旧的快捷审批接口也不能绕过质量中心。旧页面的历史状态可能仍显示 approved，应以质量中心的**有效发布版本**为准。未改写或删除原始知识库。

内容单元是 Wiki 页面、记忆条目、代码图切片或 SKILL.md。当前入口支持正文与来源文本、JSON 快照导入。**不会自动抓取任意 URL、整个原生容器或执行资产给出的脚本**。提交来源的真实性需负责人核对，哈希只证明材料未被替换。

## 2. 发布前如何评估

顺序：固定快照 → 规则检查 → 四类专用内容审阅 → 验证模型引用 → 计算 Q/E → 发布门槛 → 负责人审批。

共同检查包括用途边界、正文完整一致性、安全边界。专用检查如下：

| 类型 | 检查正文的重点 | 需要的支持材料 |
| --- | --- | --- |
| Wiki | 业务规则、事实与来源一致；读者能否正确应用 | 设计文档、代码等 |
| Chat Memory | 说话者、否定条件、纠正是否保留；不能把建议写成已确认事实 | 原始对话片段 |
| Code Graph | 节点/边、路径、行号、符号、仓库与版本；关系语义和声明范围 | 同仓库同版本代码切片 |
| Skill | 格式与配套资源；步骤前提、停止条件、正常/失败/恢复验证设计 | 说明、代码、资源或适用的原始对话 |

规则不负责假装理解全文；内容模型无工具权限，把所有资产和来源当作待审数据。系统将完整材料切为无遗漏、带位置的证据目录，模型选择证据编号，后台还原原文并再次验证位置与文字一致。这样不要求模型重新抄写 JSON 代码图，避免重排字段、添加括号或转义造成虚假引文。兼容的文字引用若未指定位置，则必须在来源内唯一。涉及事实依据的检查同时引用正文与相应类型来源。没有依据是 `unknown`，不是自动打零或声称内容错误；明确危险建议或可证实矛盾才是 `fail`。

模型超时、空响应、错误 JSON、缺少检查项、虚构引用会进入失败/待补证据，不能得到发布许可。可选的空整改建议可规范化，正文依据与检查项不能省略。

每次审阅最多进行一次针对格式/引用的纠错：把缺失项返回模型，要求补齐真实依据或改判 unknown。总超时仍由外层截止时间约束。不会因为分数低而反复评估直到通过，也不会自动替模型添加有利证据。

### Q、E 与发布条件

- **Q（0–100）**：内容本身的质量，不包含当前任务相似度。
- **E（0–100%）**：语义检查中有可核对依据的覆盖率。反面证据也计算覆盖率，因此 E=100 不代表内容正确。
- 逐项等级为 0–4：严重错误/明确缺陷/基本满足/较完整/声明范围内完整且有依据；无法判断为 null。
- 初始维度权重：正确性 40%、完整性 25%、边界 20%、可复用性 15%。需要的维度存在未知时 Q=null。
- 默认门槛：Q≥80、E=100%、所有必需检查通过，再由负责人批准。任何关键缺陷不能被其他高分抵消。
- 权重和 80 分阈值是**可审计的初始策略，尚未经过独立标注集校准**，不是“业内最优”或客观正确率。

安全是单独门槛：一个描述精确但提出危险操作的资产，即使其他维度均高分，也不能发布。

## 3. 发布与推荐使用

每个发布版本绑定资产 ID、元数据版本、内容/用途/来源哈希、评分策略、实际评估器及审批记录。审核报告不等于发布；只有有效发布指针引用的已批准版本可作为共享上下文使用。

发布读取会再次核对当前元数据版本。内容相关字段变更会增加版本并使旧发布失效。暂停当前版本后不会自动回退到较旧版本。重复提交幂等；审批中断后可重试恢复指针。

推荐时读取已认证用户的 ACL 集合；客户端不能冒用请求体里的另一个 user_id 查询资产。质量正文与发布哈希随权限过滤后的描述进入编排器，内部认证密钥不进入模型或检索器。已发布内容分 Q 参与可信度分量，U 参与历史使用分量；它们都不替代任务相关性。

Code Graph 的仓库绑定是具体代码事实，仓库不一致时不能当成当前调用图。其他项目的可迁移知识并非天然坏资产：Wiki/经验仍需结合其声明条件判断能否迁移，不能仅因项目不同全盘拒绝。完整业务条件核对不能仅靠相似分完成。

原完整注入模式仍可通过配置使用。启用渐进式披露后，先提供版本化索引卡片，再通过受控读取接口获取完整审核正文；短 Wiki 约束可提前完整注入。卡片不会计作正文暴露，预算不足或输出截断也不能记作已读。详见 [团队资产渐进式披露](PROGRESSIVE_ASSET_DISCLOSURE.md)。

### 缓存影响

团队资产动态文本从改动历史/系统前缀，改为添加在本次现有对话的末尾。不会因为资产排序变化而重写该注入器之前的整个历史。静态审阅系统提示也位于用户材料之前。

这是缓存友好的结构调整，不是命中率承诺。其他注入器、客户端历史重写、模型和服务端缓存策略仍会影响实际命中。不得把测试中的“前缀未改动”当作生产命中率提升百分比。DeepSeek 评估器单独使用 JSON 输出与非思考模式控制延迟/输出预算，不更改正常 CodeBuddy 对话模型配置。参见 [JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) 与 [思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 4. 发布后：观察、评价、反馈

1. Proxy 应用资产正文后登记曝光：团队、用户、任务、会话、轮次、发布版本、实际片段及注入前事件 ID。
2. 后续请求携带的同任务历史中，抽取新出现的用户消息、助手消息、工具调用和工具结果。注入前已有内容不算使用后证据。CodeBuddy 的 OpenAI 协议响应完成后也登记当轮助手输出，不必等待用户再发一句话。
3. 加密本地发件箱先持久化，后台提交到 Core；Core 的持久化任务再异步调用使用评估器。普通对话不用等待评估模型。
4. 评估器输出 `helpful / harmful / not_applicable / content_error / unobserved`，附具体事件的连续原文引用。
5. 自称“用了资产”、被注入、最终任务成功，都不能单独认定有帮助。只有助手自述的正/负效果会被降为未观察到足够证据。工具结果与明确用户反馈也是观察证据，不是严格因果证明。
6. 用户/负责人可补充人工反馈。内容错误生成独立复评请求；复评携带被引用的证据，不自动修改正文、不自动暂停资产。负责人决定修订、拒绝或暂停。

这里的“未来上下文”只指绑定任务的后续可见事件，不是读取用户的其他聊天、邮箱或无限未来历史。普通用户名、项目路径和原始任务文本按授权保留；凭据检测命中时不发送给评估模型。

## 5. 哪些参数会调整

| 参数 | 如何变化 | 不会做什么 |
| --- | --- | --- |
| 场景使用分 U | 同发布版本、仓库、任务类型、环境中，汇总有帮助/有害证据；模型证据权重 0.5，人工反馈 1；90 天衰减与先验收缩 | 不因沉默、未被采用而判低质 |
| 场景不适用惩罚 | not_applicable 只对相同场景形成有上限的惩罚 | 不修改其他项目的推荐或全局 Q |
| 内容复评 | content_error 触发带证据的复评，形成新报告 | 不根据模型意见改写原资产 |
| 发布阈值与保留期 | 团队审核者经策略接口修改，记录原因与版本 | 不由一段对话自动调全局权重 |

同一用户、任务、会话、发布版本、场景的重复注入只计一个相关样本。U 的空值表示没有足够观察；内部中性先验为 0.5。界面中的不确定性只是保守提示值，不是已校准的置信区间。新版本不继承旧版本的分数；多资产共同注入的观察不能被包装为独立贡献证明。

工作区、任务类型或版本没有提供时，对应维度使用 `task-local:<task_id>` 隔离，不能把所有未知环境合并成一个空字符串场景。质量中心展示按版本、仓库、任务类型及环境分组的 U 和不适用惩罚；不会把跨场景平均分直接用于推荐。

## 6. 使用方法

1. 选择团队，进入「资产质量中心」，选择自己的资产。
2. 填写一个具体内容单元、内容版本、用途、正文及支持材料；也可导入符合 `snapshotSchema` 的 JSON。
3. 提交，查看异步状态。展开每个检查项，阅读分数、证据原文和整改建议。
4. 未知项补材料，内容缺陷修正文；超时或服务失败可重试。不要为演示通过降低阈值或伪造证据。
5. 审核者填写理由，批准满足门槛的内容版本。演示团队中已发布的合成样例不代表生产审核结果。
6. CodeBuddy 绑定同团队 Agent/任务并通过 Proxy 执行工作后，回到质量中心查看使用观察、引用及反馈。没有后续可见事件时显示未观察，而不是虚构“采用”。
7. 内容错误时查看复评请求，决定修订或暂停；按场景查看 U，不能只看总览平均值。

## 7. 持久化、权限与运维

- SQLite 和 MongoDB 适配器提供 CAS 记录；内容快照与队列状态原子写在同一记录中。
- 工作进程用租约取任务，超时/崩溃可重试；每轮最多 3 次，累计最多 20 次。单团队提交有每日/排队额度；不是硬实时多租户计费系统。
- standalone 启动恢复评估任务；多实例服务模式的实例服务按请求激活。大规模多实例无人值守调度仍需独立 worker/实例注册机制。
- 保留评估报告历史、审核决定、人工反馈、事件哈希、使用评估历史与策略审计。
- 原始观察默认保留 30 天，可配置 1–365 天。窗口上限 160 个事件/200 KB。删除窗口会移除其 U 影响；已进入内容复评报告的最小引文属于版本审核材料，需按审核档案制度另外管理。
- Proxy 发件箱 AES-256-GCM 加密，独立随机密钥通过环境注入；持久化卷由实际运行用户拥有。积压上限 1000 条，重试/保留有界，耗尽后告警且不授予效果分。单写者部署，不能让多个 Proxy 共用一个本地队列目录。
- 无法解密或损坏的队列文件保留为 `.quarantined`，告警并继续后续投递，不让单条损坏数据阻塞整个队列。隔离文件仍计入容量；操作人员应核对密钥/完整性后恢复或按保留制度处置，系统不会静默丢弃它们。
- 策略编辑页面读取实际策略版本并提交 `expected_revision`；其他审核者已更新时拒绝覆盖，要求重新载入。
- 用户读取和评估受团队成员身份约束；只有负责人/reviewer 能审批、改策略、删除观察。普通成员不能读取其他成员的私有评估材料。
- 本地部署保留旧容器、数据库归档及受限权限配置备份。备份目录含凭据，已加入 gitignore，不能上传作业或仓库。

## 8. API

质量 API 前缀 `/v3/meta/asset/quality/`，请求必须包含 `team_id`，由内核解析认证用户。界面通过 Panel 的受限转发白名单调用。

- `list`、`details`：资产、版本、报告和观察。
- `submit`、`retry`、`decide`：提交/重试/审批指定版本。
- `expose`、`open-exposures`、`observe`：实际注入及后续窗口。
- `feedback`、`utility`：人工反馈与场景评分。
- `policy-get`、`policy-set`、`audit`、`rechecks`、`delete-evidence`：策略和治理。

`asset/quality/evaluate` 是兼容的只读即时评估接口；其通过报告不能直接发布，正式流程必须经持久化 submit 与 decide。

## 9. 验证与生产准入

自动化覆盖四类规则与评分、未知/缺陷/服务失败、引用校验、发布幂等与版本失效、租约争用、重启恢复、事件去重、权限边界、U 场景隔离、内容错误复评、加密发件箱和推荐集成。合成判定器只验证工程契约，不代表真实模型准确率。

`deploy/quality-v2/live-check.mjs` 在独立演示团队中调用真实配置模型；`run-proxy-smoke.mjs` 使用实际 Core/Proxy/推荐器验证审核正文、注入位置和后续观察。样例与事件明确标注合成，不能作为生产任务成功或真实贡献统计。

`MemoryCore/scripts/calibrate-quality.mjs` 接受独立人工标注及报告路径，输出不同阈值的误接纳/误拒绝/待核实数量及分类别结果。它不会自动修改线上参数。调参集与留出验收集应分离。

企业正式准入还需：按组织领域独立标注校准、权限与提示注入攻击评测、真实 CodeBuddy 流量灰度、缓存/延迟/费用监控、数据库容量压测与备份恢复演练、TLS/密钥管理/数据保留审计、多实例调度验证。不能把本地联调通过宣称为上述企业验收全部完成。原生来源可信抓取、任意 Skill 沙箱执行以及跨客户端最后一轮响应全覆盖，也不是本版已经提供的能力。

## 10. 部署与回滚

部署文件在 `deploy/quality-v2/`。正常构建使用三个 Dockerfile；本地 BuildKit 内容租约损坏时可用 `build-overlay.mjs` 基于已验证镜像生成等价源码覆盖镜像，不清理用户镜像缓存。

`deploy.mjs` 备份当前三服务的配置与数据、保留旧容器、恢复网络别名、配置 Proxy 认证和队列；`start-orchestrator.mjs --replace` 部署推荐容器。数据库/队列/认证密钥必须一起保留，不能在升级时随意生成新密钥去读取旧队列。

回滚：先停止新版服务，按备份目录 `manifest.json` 中的映射恢复旧容器名称；需要回滚数据时停服务后恢复对应归档。原容器与备份含私有内容，应限制访问。推荐服务在宿主机仅绑定回环地址 8765，并要求内部服务令牌。
