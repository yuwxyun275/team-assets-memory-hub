# Proxy 历史卡片缓存实验

本目录是**前置动态注入 vs 当前历史补齐/尾部追加**的策略消融实验，不是原版开源项目与改造版的端到端对比。不沿用旧实验中的资产乱序场景。

默认 `node evaluation/cache_history_bench/run.mjs` 只构造请求、检查同内容/无重复/前缀和压缩恢复，不请求模型。`--live` 使用现有 Proxy 配置中的 DeepSeek 凭据发出最多 111 次实际请求（108 主实验、3 校准），上限 100 万输入 Token、每次最多 16 输出 Token，只有在用户明确授权测试时运行。

模型请求在部署容器中独立的测试进程发出，不经过正在服务的 HTTP Handler，不触碰正式历史台账、资产质量状态或用户会话。真实部署的历史协调器、磁盘台账、注入管线、渐进式披露渲染器、协议适配器均被使用；ACL、推荐结果、工具输出和客户端历史采用明确标注的合成固定数据，以隔离注入策略变量。

## 场景

- 已有资产不变：六轮均使用同一组四张卡片。
- 新增资产：按业务进展逐轮提供 1、1、2、3、4、4 张卡片，未重排旧卡片。
- 压缩后继续：同样推进，但第五轮改为压缩摘要；旧卡片在摘要后汇总、新卡片追加。第五轮也新增资产，单独因果分析压缩需另设实验，本场景只比较两组完整流程。

每组/场景三个独立重复，各六轮。卡片、索引入口、提示和正文工具结果在配对请求中完全相同；不使用全量正文对比卡片制造节省。前置对照由当轮实际历史输出的相同补充块搬到系统提示末尾构造，绝不冒充开源原版。

DeepSeek `usage` 必须完整提供输入/命中/未命中/输出，字段缺失不当零处理。命中率按 Token 加权计算；报告包括首轮、三个重复、所有场景及校准，不只展示最有利的一轮。相同缓存分组请求间隔至少十秒，组间用独立 user_id 隔离；调度和服务端缓存落盘仍可能影响结果。

输入 Token 不等于未命中 Token。缓存命中不会让输入总量自动消失；需要同时看两者。仅回复 OK 的受控回放不代表任务修复效果、自由对话输出长度或生产命中率。

```sh
node evaluation/cache_history_bench/run.mjs
node evaluation/cache_history_bench/run.mjs --live
node evaluation/cache_history_bench/report.mjs output/cache-history-bench/<运行标识>
```

输出保留完整合成请求、响应 usage、请求哈希、部署源码哈希、对齐检查与独立台账；密钥只在容器内读取，不能写入结果。结果成功复制后只清理本次专属临时目录，正式服务/资产/历史不修改。发生请求错误立即保存部分结果，不自动付费重试。

## 真实 CodeBuddy 补测（另一个证据层级）

2026-09-08 已通过桌面 CodeBuddy 在隔离工作区执行真实 Redis 示例修复；当前方案 3 次人类输入、16 次上游模型调用。结果位于 `output/cache-history-bench/codebuddy-live-2026-09-08T08-15-47-811Z/report.md`。它没有真实客户端前置注入对照组，不能与上面的固定回放数值直接相减作为收益。

`prepare-codebuddy-live.mjs` 是这次演示的初始化记录，不是通用自动化入口：初始演示账号与真实客户端身份不同，造成首次 Agent 归属失败；`correct-codebuddy-live-binding.mjs` 记录了纠正过程。不要在未核对当前客户端身份、仓库绑定、授权的情况下重跑这些写入脚本。

`capture-codebuddy-live.mjs <该次目录> --final` 只读取真实 Proxy usage 和指定会话历史，执行独立本地 pytest 检查并保存证据，不向模型发送请求。该脚本绑定本次两个会话 ID；不能直接用于其他实验。最终报告已冻结，后续继续该会话时不要重采集覆盖其时间范围。
