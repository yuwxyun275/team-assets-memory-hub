# 多租户功能开关缓存降级规范

维护者：架构与产品约束维护者  
适用版本：feature-flag-service 1.4  
状态：团队权威规范

当 Redis 不可用时，读取接口允许降级到持久化仓库，但降级查询必须比普通缓存读取更严格：

1. 必须使用复合身份 `(tenant_id, key)` 查询，不能只按全局 key 查询。
2. 只能返回 `published` 状态的功能开关，禁止暴露草稿值。
3. 目标不存在、只有草稿或只存在于其他租户时，必须返回 `None`。
4. 降级响应必须把来源标记为 `database`，以便运维链路区分数据库降级和缓存命中。

这既是可用性约束，也是租户隔离边界。即使全局 key 查询能让接口恢复 200，跨租户返回数据仍属于安全缺陷。
