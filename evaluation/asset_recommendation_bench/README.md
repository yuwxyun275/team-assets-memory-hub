# 四类团队资产推荐与缓存对比：合成评测准备包

业务规则由用户授权后自行制定，所有材料明确标记为**合成评测集，不是企业专家黄金测试集**。该目录只准备数据和验证验收程序，不调用模型、不向 Memory Hub 写入、不伪造发布或贡献结果。与既有 `team_asset_bench` 和之前真实客户端缓存结果分开存放。

## 1. 本次确定的业务规则

| 样例仓库 | 三个任务 | 关键约定 |
|---|---|---|
| 多租户功能开关 | 故障回退、正常路径数据库放大、租户与发布边界 | 缓存故障仅一次数据库回退；正常未命中不读库；回退须同租户且已发布；恢复后重新走缓存 |
| 租户库存预留 | 整单预留原子性、预留幂等、重复释放 | 不足整单拒绝且不扣减；同租户同请求幂等、参数冲突报错；库存只归还一次 |
| Webhook | 原始载荷验签、跨租户事件去重、重试停止条件 | 对原始字节验 HMAC-SHA256；去重包括租户；仅 429/5xx 重试、退避 1/2/4 秒并停止 |
| 合成账单 | 金额舍入、超额抵扣、混合币种 | Decimal、逐行 ROUND_HALF_UP 两位后求和；抵扣不产生负应付；禁止混合币种 |

这些是实验合同，**不是普适业务最佳实践**。例如另一个项目允许全局共享配置或使用不同舍入规则，不能直接判那个项目的资产质量差。

## 2. 资产池的真实构成

- Wiki 100 份：项目规则、范围及依据。
- Chat Memory 100 份：围绕规则生成的明确标注“合成”的讨论记录，不冒充真实历史事故。
- Skill 100 份：规则检查流程、停止条件、证据要求。属于审查流程，不是部署脚本。
- Code Graph 100 份：从 12 个真实生成的任务基线提取 AST 定义位置及单跳同文件语法调用；包含版本和源码哈希，不宣称跨仓库动态调用链。

前三类围绕 **100 条共同政策事实**以不同资产形态呈现，存在有意的来源重叠；不是 300 条独立知识。Graph 切片也可能重叠。报告应说明这一点，不能用 400 的数量假装覆盖了 400 个独立工程问题。

每类包含 20 个质量挑战样本，共 80 个：正文与来源冲突、伪称用户批准、要求删除失败测试，或者图节点行号错误。其私有参考标签是“预期应拒绝”。其他 320 个只是“可进入真实审核”，**没有被脚本强制标为审核通过或发布**。大量来自其他项目或不同代码版本的有效资产也构成适用性干扰项。

生成的所有上传候选均为 private/candidate。下一阶段须走真实质量评估和发布流程；若实际质量评估与预期不同，应审查差异，不能绕过门禁凑足 400 个已发布资产。

## 3. 参考答案如何使用

每个任务有一份 400 项的候选参考表，记录任务—资产关系、来源、理由和允许的决策。

- 对必要业务信息按“信息组”评分：Wiki、Memory、Skill 可互为替代，覆盖其中一个有效来源即可，不要求三个都注入。
- 当前基线的相关 Code Graph 可直接定位；其他版本只能参考，须对照代码才能用于定位。
- 跨项目规则允许拒绝、仅参考或有证据地适配；不因为跨项目就自动判错。
- 质量拒绝样本应在 selected/injected 之前拦截；候选召回到它不是唯一判错依据。
- 选择、读取、采用、完成测试是不同事件。推荐正确不代表完成任务，未推荐某类资产也不自动代表任务失败。
- 合理但未预见的用法需要盲审复核。现在的标注不是能机械覆盖一切情况的完整黄金真值；复杂理由评分器尚未在本阶段实现。

参考表、参考修复、独立验收代码属于评测端材料。未来不得导入资产库或提供给 CodeBuddy。`client/tasks/*/workspace` 只包含带缺陷的源码、项目标识、任务说明和正常路径冒烟测试。

目录分离**不等于安全沙箱**。真正测试前还需确认客户端无法读取评测端文件，或使用可审计的隔离执行环境；不能仅靠一段提示词声称已经防止答案泄漏。

## 4. 验收程序已经验证什么

每个任务用独立进程运行三种代码：

1. 原始缺陷必须被目标测试发现。
2. 参考实现必须通过该仓库全部独立验收。
3. 另一种错误修复必须仍被验收发现。

12 个任务共 36 次本地校验，另有 12 次正常路径 smoke 校验。正确参考实现的通过率只是**验收程序校准**，绝不是 CodeBuddy 完成率，也不是“有资产必成功、没资产必失败”的预设结果。

行为验收覆盖关键任务条件，但不等于全部 100 条政策都经过运行验证。例如生产并发保证、真实网络与财税合规明确不在样例能力范围内。

## 5. 后续真实实验协议

三组均使用真实 CodeBuddy、相同代码基线及模型配置：

| 组别 | 唯一实验策略 |
|---|---|
| A：front_dynamic_cards | 应保留的资产卡片放系统提示后、历史对话前；仍按需读取正文 |
| B：history_append_cards | Proxy 补齐旧卡片原锚点，新增卡片追加到后文；同样按需读取正文 |
| C：no_team_assets | 不提供本次团队资产，不能通过其他 Skill 或历史记忆通道得到同一批知识 |

A 是人为构造的前置动态注入对照，不冒充已经停用某些动态注入的开源原版。A/B 保持资产呈现粒度、可用工具和任务预算相同；实际模型轨迹可以不同，因此主实验测端到端效果，不宣称所有差异都由位置单独造成。

首批选 task-01-flags 和 task-05-inventory，各跑三组，共 **6 次完整执行**。如预算与链路核验通过，正式规模可为 12 任务 × 3 组 × 3 次 = **108 次完整执行**，不是 108 个模型请求。目前没有启动这些调用。

正式开始前必须完成：

- 真实 Memory Hub 导入、质量审核、发布及数量/版本清单冻结；不使用本地数组伪装在线资产池。
- 记录真实召回各路分数及信号来源；若向量路实际使用 TF-IDF，不能标为已经调用了 Embedding 模型。
- 校验真实 CodeBuddy 用户、Agent 所有权、团队 ACL 和准确工作区绑定。
- 实现并核实按会话选择 A/B/C 的路由，不改动用户的常规对话。
- 排除旧 Skill 注入器自行更新前缀等干扰；C 组关闭所有能带入本批资产的旁路。
- 修复或明确记录上次正文读取 `last_read` 未回填等埋点问题。
- 独立缓存隔离、交替运行、固定资产/推荐权重；异步评估只写实验观察，批次内不改变其他组。
- 核对实际模型 Token、缓存字段和费用预算；首轮、失败及基础设施错误均留痕。
- 评测器与答案隔离；独立测试不可被 CodeBuddy 改写。失败或未完成不能被删除来美化完成率。

报告分别给出信息组覆盖、误用及待复核情况、独立验收完成率、输入/输出/命中/未命中 Token、耗时、费用和每成功任务成本。读取到正文不是因果贡献证明，B/C 多次对照才用于估计资产带来的任务效果。

## 6. 离线使用

```sh
python3 -S evaluation/asset_recommendation_bench/test_preparation.py -v
python3 -S evaluation/asset_recommendation_bench/build.py --output output/asset-recommendation-prep-final
```

脚本拒绝覆盖已有输出；未指定路径时创建带时间戳的新目录。所有命令均不触发模型或 Hub 网络调用。

输出中的 `assets/candidates.json` 是后续上传候选；`client/` 是任务入口；`evaluator-only/` 是私有参考判断及逐次验收原始输出；`manifest.json` 声明数据哈希、预期数量和当前未完成事项。质量标签不能随候选正文发送给被测推荐系统。

数据指纹包含生成器、业务规则、参考实现、验收测试与候选标注；验收条件修改后不能继续混用原批次结果。当前交付目录为 `output/asset-recommendation-prep-20260908`，其他 `asset-recommendation-prep-v*` / `-final` 是构建中间版，不用于正式导入。
